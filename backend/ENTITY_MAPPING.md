# BusGo persistence mapping

Verified against the live `busgo.busgo_demo` catalog on 2026-10-05. The schema contains 18 tables; `bus_amenities` is the join table for the 17 JPA entities. This document records the physical mappings and foreign keys without changing the database.

| Java entity | Table and column mapping | Relationships |
|---|---|---|
| `Amenity` | `id → amenity_id (integer)`, `name → amenity_name (varchar 40)` | Referenced by `Bus.amenityRecords` through `bus_amenities`. |
| `BoardingPoint` | `id → point_id (integer)`, `cityName → city_name (varchar 60)`, `name → point_name (varchar 80)` | `city_name → cities.city_name`; unique `(city_name, point_name)`. |
| `Booking` | `id → booking_id (bigint)`, `bookingReference → booking_reference (varchar 30)`, `user → user_id`, `schedule → schedule_id`, `status → booking_status (varchar 20)`, `paymentStatus → payment_status (varchar 20)`, `totalAmount → total_amount (numeric 10,2)`, `createdAt → booking_date (timestamptz)`, `cancelledAt → cancelled_at (timestamptz)` | `user_id → users.user_id`; `schedule_id → schedules.schedule_id`; one-to-many passengers, booking seats and payments. |
| `BookingPassenger` | `id → passenger_id (bigint)`, `booking → booking_id`, `name → passenger_name (varchar 100)`, `age → age`, `gender → gender (varchar 10)`, `seat → seat_id`, `phone → phone (varchar 20)`, `email → email (varchar 150)` | `booking_id → bookings.booking_id`; `seat_id → seats.seat_id`. |
| `BookingSeat` | `id → booking_seat_id (bigint)`, `booking → booking_id`, `schedule → schedule_id`, `seat → seat_id`, `passenger → passenger_id`, `active → is_active` | FKs to `bookings`, `schedules`, `seats`, `passengers`; `passenger_id` is unique. |
| `Bus` | `id → bus_id (integer)`, `operatorRecord → operator_id`, `primaryDriver → primary_driver_id`, `busNumber → bus_number (varchar 20)`, `busRegistrationNumber → bus_registration_number (varchar 30)`, `busType → bus_type (varchar 30)`, `seatCapacity → seat_capacity`, `model → model (varchar 60)`, `manufacturingYear → manufacturing_year`, `ac → ac`, `sleeper → sleeper`, `wifi → wifi`, `charging → charging`, `blanket → blanket`, `waterBottle → water_bottle`, `status → status (varchar 20)` | FKs to `operators` and `drivers`; unique bus number, registration number and primary driver; many-to-many amenities through `bus_amenities(bus_id, amenity_id)`. |
| `BusPerformance` | `id → performance_id (bigint)`, `bus → bus_id`, `route → route_id`, `schedule → schedule_id`, `travelDate → travel_date`, `scheduledDeparture → scheduled_departure`, `actualDeparture → actual_departure`, `scheduledArrival → scheduled_arrival`, `actualArrival → actual_arrival`, `delayMinutes → delay_minutes`, `cancelled → cancelled` | FKs to `buses`, `routes` and nullable `schedules`; unique `(bus_id, travel_date)`. |
| `CancellationPolicy` | `id → cancellation_policy_id (bigint)`, `schedule → schedule_id`, `hoursBeforeDeparture → hours_before_departure`, `refundPercentage → refund_percentage` | `schedule_id → schedules.schedule_id`; unique `(schedule_id, hours_before_departure)`. |
| `City` | `id → city_id (integer)`, `name → city_name (varchar 60)`, `stateCode → state_code (varchar 2)`, `stateName → state_name (varchar 40)`, `latitude → latitude (numeric 8,4)`, `longitude → longitude (numeric 8,4)` | `city_name` is unique and is the referenced key for route endpoints and boarding points. |
| `Driver` | `id → driver_id (integer)`, `name → driver_name (varchar 100)`, `phoneNumber → phone_number (varchar 30)`, `experienceYears → experience_years`, `licenseType → license_type (varchar 20)`, `rating → rating (numeric 2,1)` | Assigned to buses; phone number is unique. |
| `Operator` | `id → operator_id (integer)`, `name → operator_name (varchar 100)`, `rating → rating (numeric 2,1)`, `contactEmail → contact_email (varchar 150)`, `contactPhone → contact_phone (varchar 20)` | Referenced by buses; operator name is unique. |
| `Payment` | `id → payment_id (bigint)`, `booking → booking_id`, `amount → amount (numeric 10,2)`, `paymentMethod → payment_method (varchar 20)`, `paymentStatus → payment_status (varchar 20)`, `transactionReference → transaction_ref (varchar 40)`, `paidAt → paid_at`, `refundAmount → refund_amount (numeric 10,2)`, `refundedAt → refunded_at` | `booking_id → bookings.booking_id`; transaction reference is unique. |
| `Review` | `id → review_id (bigint)`, `user → user_id`, `booking → booking_id`, `bus → bus_id`, `rating → rating`, `cleanlinessRating → cleanliness_rating`, `comfortRating → comfort_rating`, `punctualityRating → punctuality_rating`, `staffRating → staff_rating`, `boardingRating → boarding_rating`, `title → review_title (varchar 150)`, `comment → review_text (text)`, `createdAt → created_at` | FKs to `users`, `bookings` and `buses`; one review per booking. |
| `Route` | `id → route_id (integer)`, `source → source_city (varchar 60)`, `destination → destination_city (varchar 60)`, `distanceKm → distance_km`, `estimatedDurationMinutes → estimated_duration_minutes` | Source and destination reference `cities.city_name`; unique `(source_city, destination_city)`. |
| `Schedule` | `id → schedule_id (bigint)`, `bus → bus_id`, `route → route_id`, `travelDate → travel_date`, `departureAt → departure_time (timestamptz)`, `arrivalAt → arrival_time (timestamptz)`, `fare → fare (numeric 10,2)`, `boardingPoint → boarding_point_id`, `droppingPoint → dropping_point_id`, `status → status (varchar 20)` | FKs to `buses`, `routes` and two `boarding_points`; unique `(bus_id, travel_date)`. |
| `Seat` | `id → seat_id (bigint)`, `bus → bus_id`, `seatNumber → seat_number (varchar 10)`, `seatType → seat_type (varchar 20)`, `rowNumber → row_number`, `columnNumber → column_number`, `deck → deck (varchar 10)` | `bus_id → buses.bus_id`; unique `(bus_id, seat_number)`. |
| `User` | `id → user_id (bigint)`, `name → full_name (varchar 100)`, `email → email (varchar 150)`, `phone → phone (varchar 20)`, `createdAt → created_at`, `passwordHash → password_hash (nullable varchar 255)`, `role → role (varchar 20)` | Email is unique; bookings and reviews reference the user. The live schema already has `password_hash` and `role`; all 1,900 existing rows have no password hash. |

Generated integer/bigint primary keys use the catalog's `GENERATED BY DEFAULT AS IDENTITY` columns. IDs for `amenities`, `boarding_points`, and `cities` are assigned from the imported dataset. JPA schema generation remains disabled. The imported identity sequences did not track the loaded maxima, so the non-destructive `002_sync_identity_sequences.sql` migration advances only behind sequences to each table's current maximum; it does not modify rows or schema.

Password hashes use Spring Security BCrypt. Supply a strong `JWT_SECRET` through the process environment; the application has no committed JWT fallback secret.
